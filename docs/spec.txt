gosper-gcf / core specification

status

This file is the current design contract for gosper-gcf.

When a design choice conflicts with Gosper / HAKMEM 101B, Gosper wins.
Aim for 100 percent Gosper/Ouroboros compliance unless a deviation is explicitly justified and agreed.

----------------------------------------------------------------------
1. mission
----------------------------------------------------------------------

Build a mathematically correct, testable Go library for exact arithmetic on generalized continued fractions in the style of Gosper / HAKMEM 101B.

Primary goals:
- mathematical correctness
- exact arithmetic only
- Gosper/Ouroboros compliance
- simplicity
- DRY implementation
- design for test

No floats anywhere in production code, tests, or correctness helpers.

Target formula:

    sqrt(3/pi^2 + e) / (tanh(sqrt(5)) - sin(69 deg))

    Approximate decimal value:
    39.662078093772932975335360621196

    Useful rational approximations:
    299647/7555          ~= 39.6620780939774983454665784249

----------------------------------------------------------------------
2. package layout
----------------------------------------------------------------------

core contains:
- exact domain types
- PQStream and RCFStream abstractions
- adapters between stream forms
- BLFT engine
- DLFT engine
- sqrt feedback controller design and future implementation
- shared evaluator control flow
- config and status codes

named contains:
- named source constructors
- convenience wrappers for source creation
- finite or procedural source definitions

----------------------------------------------------------------------
3. exact source and output model
----------------------------------------------------------------------

Generalized source term convention:

    X = p + q / X'

A PQ source provides:
- NextPQ() -> (PQTerm, tail, Status)
- Range() -> Range

A regular output stream provides:
- NextRCF() -> (RCFTerm, Status)
- Range() -> Range

Adapters currently supported:
- PQStreamFromRCF(rcf RCFStream) PQStream
- PQStreamFromRational(r Rational) PQStream

Convenience wrappers in named may re-export core constructors, but core owns the canonical implementation.

EOF is valid and triggers algebraic collapse.
Malformed client-visible source input returns status failure as soon as detected.
Impossible internal states panic.

----------------------------------------------------------------------
4. exact numeric model
----------------------------------------------------------------------

Use exact big integers and exact rationals only.

Use *big.Int internally for:
- PQTerm.p
- PQTerm.q
- RCFTerm value
- BLFT coefficients
- DLFT coefficients
- Rational numerator
- Rational denominator

Rational is exact and normalized.
Exact integer conversion means n -> n/1 with no approximation.

----------------------------------------------------------------------
5. range model
----------------------------------------------------------------------

A Range is either:
- inside interval
- outside interval

Endpoints are exact rationals with independent open/closed flags.

Inside interval invariant:
- lo <= hi

If lo == hi, the value is known exactly, but need not be an integer.

Outside interval denotes:
- (-infinity, lo] union [hi, +infinity)

Range() is defined only on live objects.
Invalid internal use panics.

For inside intervals, an emitted regular term is certified only when every value in the interval has the same floor.

For v1, outside intervals do not directly certify an emitted regular term.

----------------------------------------------------------------------
6. engine families
----------------------------------------------------------------------

BLFT state:

    Z(X,Y) = (aXY + bX + cY + d) / (eXY + fX + gY + h)

DLFT state:

    Z(X) = (aX^2 + bX + c) / (dX^2 + eX + f)

BLFT supports:
- Add
- Sub
- Mul
- Div
- Reciprocal
- unary and binary live evaluation

DLFT supports:
- Square
- finite/rational unary work
- candidate-range analysis for endpoint, rational root, and rational critical-point cases

DLFT under the current PQStream + Range contract is not yet sufficient to certify some infinite algebraic-source cases, such as Square(Sqrt2()).

Sqrt is not BLFT or DLFT.
Sqrt is to be implemented as a separate Gosper/Ouroboros feedback controller.

----------------------------------------------------------------------
7. emission, ingestion, and collapse
----------------------------------------------------------------------

General emission rule:

    Z = t + u / Z'
    Z' = u / (Z - t)

For regular output, u = 1.

BLFT ingest formulas:

If X = p + q / X', then

    (a,b,c,d;e,f,g,h) -> (pa+c, pb+d, qa, qb; pe+g, pf+h, qe, qf)

If Y = r + s / Y', then

    (a,b,c,d;e,f,g,h) -> (ra+b, sa, rc+d, sc; re+f, se, rg+h, sg)

BLFT emission:

    (a,b,c,d;e,f,g,h) -> (e,f,g,h; a-te, b-tf, c-tg, d-th)

DLFT ingest formulas for X = p + q / X':

    A = ap^2 + bp + c
    B = 2apq + bq
    C = aq^2
    D = dp^2 + ep + f
    E = 2dpq + eq
    F = dq^2

DLFT emission:

    (a,b,c;d,e,f) -> (d,e,f; a-td, b-te, c-tf)

DLFT collapse on EOF uses highest surviving degree:
- if d != 0, collapse to a/d
- else if e != 0, collapse to b/e
- else collapse to c/f

----------------------------------------------------------------------
8. public constructors and operations
----------------------------------------------------------------------

Current public constructor direction:
- NewGCF0(coeffs BLFTCoefficients)
- NewGCF1(coeffs BLFTCoefficients, x PQStream)
- NewGCF2(coeffs BLFTCoefficients, x, y PQStream)
- NewDLFT1(coeffs DLFTCoefficients, x PQStream)

Public operations currently implemented:
- Square
- Reciprocal
- Add
- Sub
- Mul
- Div

Pending public operations on the critical path:
- Sqrt
- later Sin
- later Tanh

There is no public Emit method.

----------------------------------------------------------------------
9. named sources
----------------------------------------------------------------------

Current named sources and wrappers include:
- Sqrt2()
- E()
- Pi()
- FromRational(...)

All procedural named sources should look ahead one term and provide an exact current Range whenever feasible.
All BB tests of named sources should check both emitted terms and Range() at each step.

Named sources must not require source-specific knowledge in core.
Core must work only from PQ terms, Range(), and normal collapse behavior.
Pi to 98 places on OEIS https://oeis.org/A001203

----------------------------------------------------------------------
10. sqrt design decision
----------------------------------------------------------------------

Sqrt must follow a Gosper/Ouroboros design.

Required properties:
- no preread to EOF
- no finite-only shortcut path
- no source-specific knowledge
- do not request terms until needed
- emitted output terms must feed back as the approximation stream
- finite streams are handled only by ordinary EOF collapse

Current permanent substrate already in place for sqrt:
- RCFStream interface
- PQStreamFromRCF adapter
- PQStreamFromRational constructor

Planned sqrt refinement map:

    Y_next = (Y + X / Y) / 2

where Y is the emerging output stream itself, fed back as the current approximation stream.

----------------------------------------------------------------------
11. testing rules
----------------------------------------------------------------------

For each new feature:
1. add the public stub first
2. add the planned BB signoff suite up front
3. mark pending BB tests as skipped by default
4. enable pending tests with RUN_PENDING_TESTS=1
5. as tests turn green, remove the skip logic
6. add WB tests for each R/G slice

Pending BB tests are the signoff list for a feature.

White-box tests verify:
- exact algebra formulas
- invariants
- normalization
- collapse rules
- panic paths
- engine-specific math

Black-box tests verify:
- public API behavior
- emitted prefixes
- Range() correctness
- EOF behavior
- named source behavior

Intentional panic sites should have explicit tests.

----------------------------------------------------------------------
12. non-goals for v1
----------------------------------------------------------------------

- decimal rendering API
- floating-point fallback logic
- approximate arithmetic
- hidden regular-only shortcut engines
- weakening of panic policy for impossible internal states

----------------------------------------------------------------------
13. summary of current direction
----------------------------------------------------------------------

The current architecture is:
- one public GCF
- one generalized PQStream model
- one RCFStream model
- BLFT for current binary and unary transform work
- DLFT for square and finite/rational unary work
- a planned Gosper/Ouroboros feedback controller for sqrt
- exact arithmetic everywhere
- certified regular output only
