gosper-gcf roadmap

purpose
This document is the execution roadmap for gosper-gcf.
It emphasizes sequencing, test strategy, and current development slices.

3. parked phase - sqrt
----------------------------------------------------------------------

Goal:
- finish full Sqrt(X) signoff as a live Gosper/Ouroboros feedback stream

Hard requirements:
- no preread to EOF
- no finite-only shortcut path
- no source-specific knowledge
- only PQ terms, Range(), and ordinary collapse
- emitted terms feed back as approximation terms
- ingest only when needed

Current permanent substrate already available:
- RCFStream
- PQStreamFromRCF
- PQStreamFromRational
- feedback/replay support for emitted approximation terms
- existing public ops needed for Newton refinement: Add, Div, Mul, Reciprocal, Square

Pending BB signoff list for sqrt:
- TestBB_GCF_SqrtOfTwoMatchesKnownPrefix

Status of pending sqrt tests:
- intentionally skipped by default
- runnable with RUN_PENDING_TESTS=1
- the remaining parked pending red is sqrt(2) known-prefix behavior

Related deferred BB gap outside sqrt proper:
- TestBB_SquareOfSqrt2IsExactlyTwo remains intentionally pending under the current
  DLFT infinite algebraic-source limitation

----------------------------------------------------------------------  
6. testing and workflow rules
----------------------------------------------------------------------

Feature-start workflow:
1. add public stubs
2. add full BB signoff list as pending
3. activate tests as implementation turns them green
4. add WB tests per R/G cycle
5. remove skip logic from green tests

All procedural named sources should provide exact current ranges where feasible.
All BB tests of named sources should verify Range() at each step.
Procedural named-source validation should reach at least 50 terms when practical.
Use stronger published gold standards, such as OEIS, when available and appropriate.
Use RUN_PENDING_TESTS=1 to force pending tests on and expose the full TODO surface for a feature.
