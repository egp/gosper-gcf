----------------------------------------------------------------------
3. active phase - sqrt
----------------------------------------------------------------------

Goal:
Implement Sqrt(X) as a live Gosper/Ouroboros feedback stream.

Hard requirements:
- no preread to EOF
- no finite-only shortcut path
- no source-specific knowledge
- only PQ terms, Range(), and ordinary collapse
- emitted terms feed back as approximation terms
- ingest only when needed

Current permanent substrate already available:
- RCFStream
- PQStreamFromRCF
- PQStreamFromRational
- existing public ops needed for Newton refinement:
  Add, Div, Mul, Reciprocal, Square

Pending BB signoff list for sqrt:
- TestBB_GCF_SqrtOfFourIsExactlyTwo
- TestBB_GCF_SqrtOfTwoMatchesKnownPrefix
- TestBB_GCF_SqrtOfOneIsExactlyOne
- TestBB_GCF_SqrtOfOneQuarterIsOneHalf
- TestBB_GCF_SqrtRejectsNegativeFiniteInput

Status of pending sqrt tests:
- intentionally skipped by default
- runnable with RUN_PENDING_TESTS=1
- skip logic must be removed as each test turns green

----------------------------------------------------------------------
4. immediate implementation order for sqrt
----------------------------------------------------------------------

Step 1
Add the permanent feedback-stream substrate that lets emitted RCF terms be reused as an input approximation stream.

Step 2
Build the sqrt Newton/Ouroboros controller using:
    Y_next = (Y + X / Y) / 2
with Y equal to the emerging output stream.

Step 3
Turn the easy pending BB tests green first:
- sqrt(4) = 2
- sqrt(1) = 1
- sqrt(1/4) = 1/2
- negative input rejection

Step 4
Turn sqrt(2) prefix green.

Acceptance rule:
As each pending BB test turns green, remove its skip gate.

----------------------------------------------------------------------
6. testing and workflow rules
----------------------------------------------------------------------

Feature-start workflow:
1. add public stubs
2. add full BB signoff list as pending
3. activate tests as implementation turns them green
4. add WB tests per R/G cycle
5. remove skip logic from green tests

All procedural named sources should provide exact current ranges where feasible.
All BB tests of named sources should verify Range() at each step.

Use RUN_PENDING_TESTS=1 to force pending tests on and expose the full TODO surface for a feature.
